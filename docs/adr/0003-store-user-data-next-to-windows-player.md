# Windows 실행 파일 옆에 사용자 데이터를 저장한다

첫 버전은 압축을 풀어 실행하는 Windows 휴대용 배포 형태이므로 설정, 전체 입력 수, 프리셋 JSON과 프리셋 소유 이미지를 실행 파일과 같은 폴더의 `UserData`에 저장한다. 사용자가 실행본과 데이터를 한 폴더 단위로 확인하고 이동하거나 백업할 수 있게 하려는 결정이다.

Windows 플레이어에서는 `Application.dataPath`의 상위 폴더를 실행 파일 폴더로 사용한다. Unity Editor에서는 프로젝트 폴더에 사용자 데이터를 만들지 않도록 기존 `Application.persistentDataPath`를 유지한다.

이전 개발 빌드의 `Application.persistentDataPath`에 데이터가 있고 새 `UserData`가 없으면 제품 소유 데이터만 임시 폴더에 복사한 뒤 새 위치로 확정한다. 기존 원본은 삭제하지 않으며 이미 새 위치에 데이터가 있으면 덮어쓰지 않는다.

이 방식은 `Program Files`처럼 일반 사용자 쓰기 권한이 없는 위치에서 저장할 수 없다는 제약이 있다. 첫 버전은 쓰기 가능한 폴더에 압축을 푸는 실행 형태만 지원하며 설치형 배포를 도입할 때 저장 위치 정책을 다시 검토한다.
